## Evidence and changes

1. **Allocation before reserve/debt readiness.** Baseline p1 turn 3 displayed 26/37/37 percentages while the vault was empty and card debt outstanding. Removed these from deterministic debt plans; withheld numeric investing targets from model context while locked; prevented the output checker from demanding percentages in that state. Added a shared response guard that also applies after rewrite exhaustion and provider failure. r2 shows the debt plan without investing shares.
2. **Debt stage survives signatures and plan recognition.** Removing percentages exposed that debt-plan recognition depended on the old investing text. Recognize the actual debt-plan heading. After a deposit: starter reserve first, then expensive debt; a full reserve alone never enables investing while that debt remains. r3 stage turns 7–8 kept investing closed despite a full reserve. Offline handler tests verify recognition without percentages and no model call after a signed deposit following the debt plan.
3. **Unknown reserve inputs.** The old assets question quoted a default personalized fund target despite unknown income stability/dependents, then asked multiple questions. It now asks exactly one missing reserve input before a target or investing split. Deterministic plan/standing/signature paths also defer when these inputs are missing. r3 retiree did not receive the default target as a finalized amount. Updated old tests that incorrectly required default targets.
4. **Answer the actual Vietnamese question.** Added “có nên” and “được không” intent recognition. Baseline p2 asking whether to tell his wife received a plan; r2 turn 7 answered the family-disclosure question instead.
5. **Monthly family support and shorthand no-debt statements.** The old passive-income/windfall guards lost the student's $300 allowance. Monthly family support is recorded as budget income, without counting sporadic airdrops as monthly income. “ko nợ ai” now satisfies explicit no-debt evidence. Broadened income-stability evidence to parental support; r5 proposed stable income, zero dependents and no near-term expense on a confirmation card rather than asking the same question again. That r5 card was not confirmed during the live case; offline tests verify its proposed operations.
6. **Current value, not purchase cost (CORE §3).** Removed old tool guards that rejected current crypto valuations and stored purchase cost as the portfolio value. Preserve explicit coin quantity; current self-reported values go through confirmation; a purchase cost alone cannot become current value. Removed obsolete deterministic purchase-cost answers. Offline tests cover $1,600 purchase cost vs $1,200 current value and 60M VND cost vs 42M VND current value. r4 live ETH update proposed $2,000, left saved $3,000 unchanged before confirmation, then saved $2,000 in Crypto after confirmation.
7. **Action claims and outdated guidance.** Replaced old above/below-share examples with the CORE leader rule. Explicitly ground whether the vault exists. Expanded false-card detection and block unsupported “card is ready” claims even after retries fail. The final false-card guard has offline coverage; no full live persona rerun followed this last guard change.
8. **Evaluation fixture source selection.** The old runner selected the first eligible source, which could invent a transfer from a term deposit when a user designated untracked bank money as Safety. Future runs use an eligible source of the same type or new/untracked money. Harness selftest passes. Existing r1/r3 retiree confirmation totals retain the old fixture behavior and are not valid evidence about that source choice.
