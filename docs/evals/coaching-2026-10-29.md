## Improvements

- A small coaching module supplies relevant context for investment losses, chasing losses, FOMO/borrowing and possible recovery-fee fraud. It changes reply priorities, not financial calculations or transaction permissions. A concern without a question mark can be answered before onboarding.
- Replace the unsupported “most low caps lose 90–99% / would you dare” wording with a calm explanation of possible loss and its consequence for bills/goals. Preserve the existing once-only situation and its locks.
- Add a conservative evidence filter before numeric validation and placement cards: historical losses, quoted examples, hypothetical chains and third-party amounts are not current personal balances. Current facts can still be recorded in a mixed message. Cost-basis declarations such as “I put $1,000 into BTC” remain valid.
- Expand the reviewed bilingual zero-model lesson library from 5 to 10 topics: budgeting, debt repayment methods, near-term goals, FOMO and recovery scams join the original lessons. Narrow standalone matching remains intentional; mixed/personal requests go through the agent.
- Extend the existing eval harness; no paid grader. Fix one stale offline-flow assertion that expected a model call for a now-deterministic lesson, and separately check that unfamiliar “why” questions still get TEACH mode.

## Bounded live inspection

One run of six independent, synthetic questions, with the same model (`gpt-5.4-mini`). No actual founder/customer story or production profile is stored. No paired baseline, repeated trials or paid judge, so no accuracy percentage or cost reduction is claimed.

| Scenario | Observed behavior |
| --- | --- |
| Loss and self-blame; wants to be heard | Acknowledged the loss, no onboarding or trade; wording still echoed the negative self-label while refuting it |

## Reproduce and continue

Run `bun run eval:education`, `bun run flow` and `bun scripts/kb-check.ts` without paying for models. For an explicitly budgeted real run: `bun scripts/education-eval.ts --live --coaching`; `--only <substring>` selects a case. It allows at most 12 OpenAI calls and 100k reported tokens; a single in-flight response may take usage over the token threshold. Cap exhaustion or API errors fail the run; no retry/fallback spending. Raw reports remain ignored.

The evidence filter is a conservative language heuristic, not a semantic proof. It may reject a valid ambiguous statement and need a separate clear declaration. It does not prove every number belongs to the right asset when identical numbers occur in different clauses. Preserve this caution when adding languages or recording tools.

The live sample also shows room to improve warmth: the first reply repeats the user's negative label while denying it. The final instruction explicitly says to name the feeling instead and listen without adding a plan when asked; that wording adjustment has not had another paid run. Future tests should measure listening-only responses, multi-turn rebuilding plans with realistic profiles, ability to resume the user's existing plan, and declines to share. Extend the same fixtures rather than replacing the framework or assuming a bigger model/database solves these issues. Coaching adds prompt context; there is no measured app-wide cost saving in this change.
