## Contract V2 (decided 2026-11-07)

- Vault password = 24 chars in groups of 4 (`ABCD-EFGH-…`), created in the browser. The browser derives a secp256k1 key; the vault stores only that key's address (`passwordKey`). The password never goes on chain.
- `withdraw(amount, to, deadline, sig)`: owner wallet sends + EIP-712 signature by the password key over (amount, to, nonce, deadline). `importVault(deadline, sig)`: new wallet sends + signature over (newOwner = sender, nonce, deadline). The factory updates `getVault`; import is refused if the new wallet already has a vault.
- Factory: no guardian. The owner only sets the fee (0 = off), fee recipient, and pauses new vaults. `createVault(passwordKey)`.
- **Key derivation is frozen:** key = keccak256("MoonSafe vault password v1" ‖ password) mod n, no slow KDF (24 random chars = 120 bits). Changing it later would make old vaults unopenable. Proposed alphabet: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`.
- Deposits stay as they are: `deposit` (owner), `depositFor` (anyone, through an app button), `receive()` rejects direct sends. ERC-20-style USDC transfers (0x3600…) into a vault may not be blocked (untested on Arc), so the app should show `getBalance()` and never sum events.
- Password change is undefined in CORE. If the paper leaks, the only path today is withdrawing everything to a new vault.
